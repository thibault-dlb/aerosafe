# API

The API only has its health check and empty routers so far. This page lists what the project sheet and the specifications require of it, and will be completed during development.

The API documentation is kept in the repository as Markdown and/or generated automatically (§VIII.2).

## Requirements

Source: project sheet §8 (a FastAPI API); specifications §II, §VI.1.1, §VII.1 and §III.2 for the role checks, the protection of endpoints and the 2-second target.

- The backend is a FastAPI application exposing business services and data.
- API endpoints check the caller's role before running a restricted operation.
- Stored data and API endpoints are protected (NF-02).
- Indicative performance target: a response in under 2 seconds on a standard search (NF-01).

## Authentication

Decided on 2026-11-03, see [technology choices](technology-choices.md#authentication).

- The API itself handles accounts: sign-up, login, logout and refresh. Passwords are hashed with argon2id.
- Login returns a short-lived access token (JWT, about 15 minutes) and sets a refresh token in an `HttpOnly` cookie. Only the hash of the refresh token is stored, so it can be revoked.
- Every request sends `Authorization: Bearer <access_token>`.
- The API checks the JWT signature and expiry.
- The role (`User` or `Supervisor`) is read from the token and checked before any restricted operation.
- A missing, invalid or expired token returns 401. A valid token without the required role returns 403.
- Failed logins are throttled.
- Deactivating or anonymising an account revokes its refresh tokens.
- The Swagger UI generated by FastAPI offers an Authorize button for testing.

Token claims, endpoint paths and environment variables are `TBD` until implemented.

### Aircraft (`/api/v1/aircraft`)

Work package `feat/aircraft-lookup` (BF-04 to BF-07, UC-01). Every endpoint needs an authenticated caller, User or Supervisor; without a valid token it answers 401. Identifiers in paths and responses are the public ULIDs, never the internal keys.

| Method and path | Purpose | Answers |
| --- | --- | --- |
| `GET /aircraft` | Search aircraft | 200 with a list, possibly empty; 422 for invalid criteria |
| `GET /aircraft/{aircraft_id}` | Aircraft record | 200; 404 if unknown or deleted |
| `GET /aircraft/{aircraft_id}/observations` | Observation history | 200, oldest first; 404; 422 |
| `GET /aircraft/{aircraft_id}/flights` | Flights of the aircraft | 200, most recent first; 404 |

Query parameters of `GET /aircraft`. Every criterion is optional and they are combined (AND). Results are sorted by ICAO24 address.

| Parameter | Rule |
| --- | --- |
| `icao24` | Start of the address, 1 to 6 hexadecimal characters, case ignored |
| `registration` | Part of the registration, case ignored |
| `airline` | Part of the airline name or code, case ignored |
| `south`, `west`, `north`, `east` | Area in degrees (WGS 84), all four or none. It applies to the latest known position of each aircraft |
| `limit` | 1 to 200, default 50 |

Aircraft (search result and record):

```json
{
  "id": "01JC5Z8N0Q3V9X2K7M4T6B1R8D",
  "icao24": "3c6444",
  "registration": "D-AIBD",
  "model": "Airbus A319",
  "airline": "Lufthansa",
  "last_contact_at": "2026-11-09T10:00:00Z",
  "latitude": 48.85,
  "longitude": 2.35
}
```

`model`, `airline` and `registration` are `null` when unknown; the last contact and the position are `null` when the aircraft never sent any.

`GET /aircraft/{aircraft_id}/observations` takes `start` and `end` (ISO 8601, inclusive, both optional; `start` must not be after `end`) and `limit` (1 to 5 000, default 500). It returns the latest `limit` observations of the period, in chronological order:

```json
{
  "last_contact_at": "2026-11-09T10:00:00Z",
  "position_at": "2026-11-09T09:59:58Z",
  "latitude": 48.85,
  "longitude": 2.35,
  "altitude": 10000.0,
  "speed": 230.5,
  "heading": 90.0,
  "on_ground": false,
  "flight_id": "01JC5Z9A2B3C4D5E6F7G8H9J0K"
}
```

Units: altitude in metres, speed in metres per second, heading in degrees clockwise from north. Any measured value is `null` when OpenSky did not send it; `flight_id` is `null` for an observation that belongs to no flight.

`GET /aircraft/{aircraft_id}/flights` takes `limit` (1 to 200, default 50) and returns flight summaries, described below.

### Flights (`/api/v1/flights`)

Work package `feat/aircraft-lookup` (BF-07, BF-08, UC-02). Users and Supervisors can both view trajectories (team decision C-06).

| Method and path | Purpose | Answers |
| --- | --- | --- |
| `GET /flights/{flight_id}` | Trajectory, missing segments and statistics of a flight | 200; 404 if unknown or deleted; 401 |

Flight summary, also returned by `GET /aircraft/{aircraft_id}/flights`:

```json
{
  "id": "01JC5Z9A2B3C4D5E6F7G8H9J0K",
  "aircraft_id": "01JC5Z8N0Q3V9X2K7M4T6B1R8D",
  "icao24": "3c6444",
  "registration": "D-AIBD",
  "callsign": "DLH4AB",
  "started_at": "2026-11-09T09:00:00Z",
  "ended_at": null,
  "origin": "Frankfurt",
  "destination": null
}
```

`ended_at` is `null` while the flight goes on. `GET /flights/{flight_id}` adds:

- `trajectory`: the observations of the flight, oldest first, in the format above (at most 10 000);
- `gaps`: the missing segments, `{"start", "end", "duration_seconds"}`. Two consecutive positions more than 300 seconds apart are not joined, which is the upper bound of the window of rules R3 to R5. The partial trajectory is still returned (UC-02, alternative flow 2a);
- `statistics`: `observation_count`, `duration_seconds` (first to last observation), `distance_km` (great-circle length, gaps excluded), `mean_altitude` and `max_altitude` in metres, `mean_speed` and `max_speed` in metres per second. A mean or maximum is `null` when no observation has the value.

### Collection (`/api/v1/collection`)

Every endpoint needs the Supervisor role (401 without a token, 403 with another role). Run times are UTC.

| Method and path | Purpose | Answer |
| --- | --- | --- |
| `GET /collection/status` | State of the collection: enabled on this instance, paused, cycle running, profile, period, credits per day and daily quota, anonymous or authenticated access, wait after a 429, last run and last successful run | `200` |
| `GET /collection/runs?limit=20&offset=0` | Latest runs, newest first. `limit` from 1 to 100 | `200`, `422` if out of range |
| `POST /collection/run` | Runs one cycle now and returns it. It uses OpenSky credits | `200`, `409` when the collection is disabled on this instance or a cycle is already running |
| `POST /collection/pause` | Suspends the periodic collection, without stopping the API. Later cycles are recorded as `SKIPPED` | `200` with the status |
| `POST /collection/resume` | Resumes the periodic collection | `200` with the status |

A run has `started_at` (also the `now` given to the rules engine), `ended_at`, `status` (`SUCCESS`, `PARTIAL` when some state vectors were rejected, `FAILED`, `RATE_LIMITED`, `SKIPPED`), `profile`, `received`, `stored` (new observations), `rejected`, `remaining_credits` (from OpenSky), `error` and `evaluation_error` (a failure of the rules engine, which never cancels the collection).

Each run is written once to `EXECUTION_COLLECTE`, complete, with its end set after the rules evaluation. The pause is kept in `PARAMETRE_COLLECTE`, so it survives a restart of the API.

Configuration, in `.env`:

| Variable | Default | Meaning |
| --- | --- | --- |
| `COLLECTION_ENABLED` | `false` | Whether this instance collects. Only one instance collects with the group account at a time |
| `COLLECTION_PROFILE` | `ILE_DE_FRANCE` | `ILE_DE_FRANCE` (every 30 s) or `FRANCE` (every 120 s), see [architecture](architecture.md#data-source) |
| `COLLECTION_FLIGHT_GAP_MINUTES` | `30` | Maximum gap between two observations of the same flight (D-06) |
| `COLLECTION_BBOX_ILE_DE_FRANCE`, `COLLECTION_BBOX_FRANCE` | see [OpenSky Network](opensky.md#collection) | Areas, as `lat_min,lat_max,lon_min,lon_max` |
| `OPENSKY_CLIENT_ID`, `OPENSKY_CLIENT_SECRET` | empty | OAuth2 API client of the group account; empty means anonymous access |

The API refuses to start when the profile would use more than the 4 000 daily credits of an account. With anonymous access the credits run out after a few hours; OpenSky then answers 429 and the collection waits for the delay it announces.
